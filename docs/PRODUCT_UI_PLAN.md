# Auralis Mobile 正式产品 UI 计划

本文档冻结 Technical Spike 通过后首批正式产品界面的信息架构、复用边界和实施顺序。它不改变 `PRODUCT.md`、`METADATA.md` 与 `ARCHITECTURE.md` 中的产品和数据语义。

## 1. 首批交付目标

首批正式 UI 建立以下完整路径：

1. 首次进入时选择一个或多个本地曲库目录；
2. 扫描后默认以专辑浏览收藏；
3. 进入专辑查看按 Disc Number / Track Number 排序的曲目；
4. 点击曲目后，将当前资料库排序中的全部可播放歌曲交给现有 Media3 服务形成播放队列，并从所点曲目开始播放；
5. 使用常驻迷你播放器进入完整播放页；
6. 后台播放和通知栏控制继续生效。

临时调试界面保留为开发验收工具，但不再承担产品入口，也不继续扩展产品功能。

## 2. 信息架构

主导航采用四个底部目的地，顺序固定为：

- **首页**：应用默认入口；当前阶段仅保留占位，不提前设计具体内容；
- **资料库**：浏览用户拥有的本地音乐；提供专辑、歌曲、歌单和流派四个无数量栏目；
- **漫游**：用于没有明确目标时进入本地曲库；当前阶段仅保留占位，不提前冻结具体能力；
- **搜索**：搜索本地曲库。

全局能力不占用四个主目的地：

- 四个主目的地放在不吸附屏幕底边的同一个悬浮圆角胶囊中；
- 曲库目录、重新扫描、诊断日志和设置放入顶部菜单；
- 迷你播放器作为独立悬浮层放在导航上方，仅在存在当前播放项目时显示；
- 点击迷你播放器进入完整播放页。

导航层级：

```text
应用入口
├─ 无曲库目录 → 首次使用页 → 系统目录选择器 → 扫描
└─ 已有曲库
   ├─ 首页
   ├─ 资料库
   │  ├─ 专辑 → 专辑详情 → 播放页
   │  ├─ 歌曲 → 播放页
   │  ├─ 歌单 → 歌单详情 → 播放页
   │  └─ 流派 → 流派歌曲列表
   ├─ 漫游
   ├─ 搜索 → 搜索结果 → 对应详情 / 播放页
   └─ 曲库与设置 → 目录管理 / 重新扫描 / 诊断导出
```

## 3. 首批页面

### 3.1 首次使用页

- 说明 Auralis 只读取用户选择的本地目录；
- 主操作为“选择音乐目录”；
- 明确不申请全盘存储权限、不上传音乐；
- 选择完成后显示扫描进度；
- 权限失败或目录不可访问时提供重新选择入口，不清空已有曲库。

### 3.2 专辑页

- 默认使用双列封面网格；右上角可切换 1–5 列封面网格、紧凑列表或无封面纯文字布局，也可在内容区域通过双指捏合或放大沿相同序列切换，选择由 DataStore 持久化；
- 卡片显示封面、Album、Album Artist；
- 仅单列封面网格在专辑名称同一行右侧显示完整 Date，右端与封面右边缘对齐；日期缺失显示“未知日期”，长专辑名省略；
- 同名 Album 的不同 Album Artist 或 Date 必须保持为不同卡片；
- 缺失 Album Artist 显示“未知 Album Artist”，不得用 Artist 替代；
- 无 Album 的曲目不伪造共享“未知专辑”，在独立入口中显示；
- 封面不可用时显示稳定占位图，不阻塞列表滚动。

### 3.3 专辑详情页

- 顶部以封面为主要视觉元素；
- 展示 Album、Album Artist、完整 `YYYY-MM-DD` Date；
- 提供“播放”操作；
- 曲目严格按 Disc Number、Track Number 和稳定回退顺序排列；
- 多碟专辑按碟分组；
- 曲目显示 Title 与 Artist；
- 没有可用 Active Source 的曲目灰显，并提供可理解的错误原因。

### 3.4 曲目页

- 标题下提供即时搜索框，仅匹配 Title、Artist、Album、Album Artist，不匹配 Genre；忽略大小写，支持简繁字符等价匹配、部分文字匹配和清除，筛选后保持原有顺序，无结果时显示提示；简繁归一化仅用于搜索，不改变原始显示和身份键，不做同音或地区词汇扩展；
- 展示全部逻辑 Track，不展示重复物理源；
- 页面正文只显示内容标题“歌曲”，不显示“全部曲目”、曲目数量或排序说明；内容标题完全离开视口后，返回键右侧淡入同名顶部标题，内容标题重新出现时顶部标题隐藏；
- 行项目显示 Title、Artist、Album 与封面缩略图；
- 点击可播放的 Track 时，继续使用 `TrackId → Active Source → SAF URI` 链路；
- 不可用 Track 保留在列表中并灰显，不能静默隐藏。

### 流派页（当前范围）

- 流派列表只显示名称，行间使用细分隔线，不显示封面或数量；点击进入对应流派的歌曲列表，复用歌曲页搜索和播放入口；
- 歌曲按真实 GenreId 关联筛选，保持歌曲页既定顺序，多流派歌曲可出现在多个入口中，不按名称模糊归类；
- 读取 Room 中仍有关联歌曲的流派，沿用已解析的多值关系，不重新拆分名称、不合并不同流派身份；
- 按字母／拼音稳定排序，无数据时显示“暂无流派”；不可播放歌曲的流派不因此隐藏；
- 标题沿用歌曲页的滚动后顶部标题切换。

### 3.5 迷你播放器

- 显示当前曲目的封面、Title、Artist；
- 提供播放/暂停；
- 点击主体进入完整播放页；
- 状态完全来自 `MediaController`，Compose 不持有 ExoPlayer；
- 没有当前媒体项目时不显示。

### 3.6 播放页

- 竖屏单栏，不实现横屏专用布局；
- 封面与歌词是核心内容，首批允许在同一页面切换；
- 歌词优先按当前音频源读取内嵌内容，缺失时读取同目录音频同名 `.lrc`（支持 UTF-8、带 BOM 的 UTF-16）；时间轴歌词高亮当前行并自动滚动，手动滚动后通过“回到当前歌词”恢复跟随，纯文字歌词可自由滚动；缺失与读取失败分别提示，失败可重试。歌词只读，不写入曲库身份或搜索索引；
- 展示 Title、Artist、Album；
- 提供进度、上一首、播放/暂停、下一首；
- 播放模式固定为五种互斥状态：顺序播放、列表循环、单曲循环、随机播放、随机专辑。随机播放采用无权重洗牌，每轮歌曲各出现一次；随机专辑以真实 AlbumId 为随机单元，专辑内部严格按 Disc Number / Track Number 播放，无专辑歌曲作为单曲块参与；两种随机模式每轮结束后重新洗牌，不加入艺术家间隔、偏好权重或历史避让等“智能随机”；
- 完整播放器提供播放模式入口，单击后使用 Liquid Glass 底部面板直接选择五种模式，不通过连续点击循环切换；模式作为轻量偏好持久化，切换时保留当前歌曲与进度，但不恢复应用退出前的歌曲或播放进度；
- 播放模式面板使用与设备屏幕底部圆角同心的自适应圆角；五种模式图标统一使用底部导航同系列的 Material Icons Rounded，不再维护另一套自绘图标；
- 播放时按产品规则支持保持屏幕常亮；
- 不保存退出时播放状态，不恢复上次进度，不产生播放历史或统计。

## 4. 后续 v1 页面

以下页面在首批闭环稳定后实现：

- 艺术家列表与艺术家详情；
- 搜索页，固定搜索 Title、Artist、Album Artist、Album、Genre；
- 歌单列表与详情；
- 新建、重命名、删除歌单；
- 添加、移除和手动排序歌单曲目；
- 曲库目录管理、重新扫描、诊断导出和轻量设置。

## 5. 页面共有状态

所有曲库页面必须显式处理：

- **加载中**：只用于首次读取或必要刷新，不用全屏加载遮挡后台播放；
- **空曲库**：引导选择目录或重新扫描；
- **扫描中**：显示可理解的进度状态，已存在的曲库仍可浏览；
- **部分异常**：可访问内容照常显示，同时提示存在目录或文件问题；
- **不可用条目**：保留并灰显，展示访问、解析或播放失败原因；
- **正常内容**：列表、详情和播放状态由 Room / MediaController 的流式状态驱动。

## 6. 数据与状态边界

- Room 继续作为曲库和歌单的唯一真源；
- UI 只读取逻辑 Track、Album、Artist 及 Active Source 投影；
- 扫描、解析和对账不进入 Composable；
- 播放状态只通过现有 `PlaybackControllerConnection` 的产品化接口进入 UI；
- 页面 ViewModel 暴露不可变 `StateFlow<UiState>`；
- 导航参数只传稳定 ID，例如 `AlbumId`、`ArtistId`、`TrackId`、`PlaylistId`；
- 不把完整数据库实体或 SAF URI作为导航参数。

正式 UI 开工前需要补充响应式 Room 查询：专辑摘要、专辑曲目、全部曲目、艺术家摘要和详情。查询应直接产生页面需要的只读投影，避免在 Composable 中逐条查询关系。

## 7. 封面与歌词缺口

当前元数据链路能读取内嵌封面和歌词，但 Room 尚未保存可供正式 UI 高效读取的内容，必须先补充独立内容层：

- 使用 Coil 负责图片请求、内存缓存、磁盘缓存和取消；
- 封面来源顺序严格保持“内嵌 Artwork → 同目录 `cover` → 同目录 `COVER`”；
- 缓存键包含 Active Source 身份与文件指纹，源变化后自动失效；
- 不把大图字节直接塞进页面状态或主曲库关系表；
- 歌词来源顺序严格保持“内嵌歌词 → 同目录 `.lrc`”；
- 不搜索歌词内容。

实现前优先审计并复用 Auxio/Musikr 成熟的本地封面缓存与 SAF 内容加载思路；只移植适合当前架构的最小部分，并记录固定上游版本与许可证。若 Coil 官方能力已经覆盖对应环节，则直接使用官方能力。

## 8. 组件复用边界

优先复用：

- Jetpack Compose Material 3：页面骨架、导航栏、Top App Bar、对话框、Sheet、列表和按钮；
- AndroidLiquidGlass / Backdrop：悬浮导航和迷你播放器的实时背景采样与玻璃效果；
- Navigation Compose：页面导航与返回栈；
- Coil：本地封面加载和缓存；
- Media3 `MediaController`：播放状态、队列和控制；
- Room + Flow：响应式曲库与歌单查询；
- Activity Result API / SAF：目录选择与诊断文件导出。

Auralis 只自行实现产品特有部分：

- Album / Track / Artist 的展示投影与未知字段规则；
- Active Source 选择后的可用性表达；
- 专辑优先的信息层级；
- 播放页的视觉组合；
- Auralis 的歌单数据模型和排序语义。

不引入新的依赖注入框架、通用 Redux/MVI 框架或自建导航系统。Backdrop 固定为 `2.0.0`；升级前必须重新验证 Kotlin / Compose 编译兼容性和 Find X9 性能。新增其他依赖必须先证明现有 AndroidX、Compose、Backdrop、Coil 或 Media3 不能满足需求。

## 9. 视觉方向

- 以专辑封面和内容为视觉中心，减少装饰性容器；
- 默认颜色体系固定为 `steel_blue`：冷白 `#F5F6F8`、石墨黑 `#0D0F12` 与低饱和钢蓝（浅色 `#3E628F`、深色 `#91B8E6`）；不使用暖色背景或第二强调色；
- 颜色实现分为原始色板、Material 语义映射与 Auralis 扩展 Token，页面不得直接引用主题十六进制色值；颜色体系使用稳定 `key` 注册，未来新增体系时不改变页面组件；
- 外观模式内置“跟随系统 / 浅色 / 深色”三档并由 DataStore 持久化，用户选择优先于系统主题；
- 浮动底部导航在 Android 12 及以上读取设备底部屏幕圆角，以水平内缩后的同心半径生成外轮廓，并受组件半高上限约束；无法读取时使用设计 Token 回退值；
- 底部导航仅显示图标，不显示图标下文字；导航栏高度为 `56dp`，每个入口保留 `48dp` 点击高度；
- 专辑列表页不显示收藏说明和专辑数量，只保留内容标题“专辑”；内容标题完全离开视口后，返回键右侧淡入同名顶部标题，内容标题重新出现时顶部标题隐藏；
- 歌曲列表页只保留内容标题“歌曲”，不显示数量和排序说明，并与专辑列表页使用相同的滚动标题切换逻辑；默认顺序依次按 Album Artist 的字母/拼音键、专辑 Date 升序、专辑、Disc Number、Track Number 排列，任一缺失排序字段置于对应分组末尾；
- 专辑列表页右上角提供布局切换，支持 1–5 列封面网格、列表和无封面布局；默认双列，选择持久化且不改变专辑排序与身份语义；
- 专辑内容区域支持双指缩放切换布局，顺序固定为“1 列 → 2 列 → 3 列 → 4 列 → 5 列 → 列表 → 无封面”：向内捏合沿此顺序提高密度，向外放大则反向切换；单指纵向滚动不受影响；
- 专辑布局切换默认使用淡入淡出：内容淡出后在不可见状态完成布局切换，再显示新布局，不向用户展示重排过程；“连续重排”作为可持久化的外观选项保留，启用后保持每张专辑的视觉身份并连续改变位置、尺寸和行高；
- 资料库主标题使用离线打包的 Noto Serif SC 粗明体子集；标题下沿使用全宽分隔线并紧接栏目，栏目保持裸图标、紧凑行高、无右箭头，栏目间分隔线从文字列开始；
- 使用 Material 3 的可访问性、触控尺寸和系统深浅色基础，但建立 Auralis 自己的固定色彩与排版，不继续使用模板默认紫色；
- 液态玻璃只用于底部操作层，不覆盖大面积正文；信息层级仍优先于玻璃效果和复杂动画；
- 收纳封面进度轨道取色使用官方 Material Color Utilities 的 Celebi → Score → HCT：请求 `128×128` 封面采样，最多量化为 128 色；无合适彩色候选时保留封面主要中性色。深色主题 Tone 限制为 70–80，浅色主题为 35–45，不强制提高彩度；保留进程缓存和颜色过渡，不改变应用整体主题；
- 底部结构固定为“上层迷你播放器 + 下层四栏导航胶囊”，整体与屏幕底边留出安全距离；
- 迷你播放器支持长按整条 playbar 后向下拖动收纳：长按后页面内容虚化，仅 playbar 与底部导航保持清晰；playbar 整体浮起并以有上限的阻尼位移跟随手指，不与导航重叠。向上拖动只提供幅度更小、阻力更强的橡皮筋反馈，松手后回弹且不触发功能。收纳只依据手指是否在导航栏真实区域内松开，命中后才继续收进导航中央；导航临时变为“首页、资料库、当前封面、漫游、搜索”五项，中央封面不是页面入口，单击切换播放／暂停；长按后向上滑动至少 `24dp` 且上滑距离大于横向偏移，松手恢复完整迷你播放器，长按提供触觉反馈，应用重启后默认展开；
- 收纳封面保持与导航图标一致的视觉尺寸，外围使用封面主色的高频不规则波浪进度轨道：轨道沿圆角方形封面的外轮廓连续绘制，所有波动只朝外并保留固定间隙，不得覆盖封面；每张封面稳定生成一至两个更明显的强调波峰，其余波纹保持细密；已播放部分较深、未播放部分较浅，不为封面增加独立玻璃底座；
- 迷你播放器提供“上一首 / 播放暂停 / 下一首”三个控制入口；上下首统一使用方向相反的双圆角三角形，不使用带竖线的 Skip 图标，并随深浅色主题切换前景色；完整播放页使用同一套上下首图标语义；应用内、流体云、锁屏和其他系统媒体入口统一操作 Media3 播放队列，不在界面层另行计算上下首；
- 底部导航图标与文字直接显示在玻璃胶囊上，不使用选中项圆角底板或图标外层阴影；选中状态只通过强调色与字重表达；
- 默认视觉为折射、景深和轻微色散更明显的 `Liquid Glass`；保留较高模糊和遮罩强度的“磨砂玻璃”作为可切换界面偏好；
- 玻璃风格属于轻量设置，正式接入时存入 DataStore，不进入 Room，也不改变页面结构与操作语义；
- 列表密度适合单手浏览，主要操作位于拇指容易触达的位置；
- 动画只用于导航、迷你播放器展开和内容状态变化；
- Find X9 / ColorOS 16 是首要真机验收环境，但布局不得依赖 ColorOS 专有 API。

## 10. 实施顺序与门槛

### Phase UI-1：数据与应用外壳

- 响应式 Room 页面投影；
- 正式导航骨架和产品入口；
- 首次使用页、空状态、扫描状态；
- 调试页迁移到独立开发入口；
- 封面加载与缓存最小链路。

门槛：冷启动、目录选择、扫描、进程重建后均能进入正确页面；无网络权限。

### Phase UI-2：专辑播放闭环

- 专辑页；
- 专辑详情；
